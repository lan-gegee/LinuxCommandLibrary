# TAGLINE

面向 Apple Silicon 的原生 MiniMax-H3 视频与音频推理 CLI

# TLDR

**检查**本地 MiniMax-H3 检查点及所选 Metal 设备

```h3 --info -d [./MiniMax-H3]```

**根据提示词生成短视频**（均衡的默认质量设置）

```h3 -d [./MiniMax-H3] -p "[A red fox walks through snow]" --width 512 --height 512 --frames 22 --steps 20 --layers 45 --reuse 2 -o [outputs/fox.mp4]```

**启动交互式会话**，模型在多次提示之间保持驻留

```h3 -d [./MiniMax-H3] --width 512 --height 512 --steps 6```

**以首帧和尾帧作为条件**

```h3 -d [./MiniMax-H3] -p "[Continue the scene]" --first-frame [start.png] --last-frame [end.png] -o [out.mp4]```

**使用有序图像参考**（Ref2VA 路径）

```h3 -d [./MiniMax-H3] -p "[Use the subject in Picture 1]" --ref-image [person.png] -o [out.mp4]```

**分析** Metal 计时和峰值内存

```h3 --profile -d [./MiniMax-H3] -p "[prompt]" --width 512 --height 512 -o [out.mp4]```

# SYNOPSIS

**h3** **-d** _MODEL_DIR_ [**-p** _PROMPT_] [**-o** _OUTPUT_] [_options_]

**h3** **-d** _MODEL_DIR_ **--info**

# DESCRIPTION

**h3**（项目名 **h3-metal** / 仓库 **h3.c**）是 Salvatore Sanfilippo 面向 Apple Silicon 的原生 MiniMax-H3 推理引擎。它加载本地 Hugging Face 风格的 **MiniMax-H3** 检查点，在 Metal 上运行 DiT 和 VAE，并输出音画同步的 H.264 视频加 AAC 音频（通过 **PATH** 中的 **ffmpeg** / **ffprobe**）。

不带 **-p** 时，程序会启动交互式会话：输入提示词即可生成带编号的视频，同时 BF16 提示条件化和解码器保持驻留。会话内的 bang 命令（如 **!seed**、**!first**、**!last**、**!ref-image** 和 **!help**）无需重启即可控制生成过程。

带 **-p** 时，生成是一次性的。质量与速度由相互独立的旋钮控制：**--steps**（去噪轮数）、**--layers**（激活的 DiT 块数）、**--reuse** 或 **--core-reuse**（完整去噪器的运行频率）、可选的 **--token-reduction**，以及可选的较小 **--render-width** / **--render-height**（随后上采样到最终画布尺寸）。首帧/尾帧标志选择 FL2VA 路径；**--ref-image**、**--ref-video** 及相关标志选择有序的 Ref2VA 路径。

该工具面向拥有大容量统一内存的 Mac GPU（M3/M5 级别）。它不是可移植的 Linux GPU 运行时；请在 macOS 上针对本地模型目录用 **make** 构建。

# PARAMETERS

**-d**, **--model-dir** _PATH_

> 本地 MiniMax-H3 检查点目录（必填）。

**-p**, **--prompt** _TEXT_

> 生成提示词。省略则进入交互式会话。

**-o**, **--output** _PATH_

> 输出的 MP4 路径（默认为 **outputs/h3.mp4**）。空字符串表示禁用编码。

**--width** _N_, **--height** _N_

> 输出画布尺寸（32 的倍数；乘积有限制）。默认值取决于版本（通常为 864×480）。

**--render-width** _N_, **--render-height** _N_

> 较小的内部 DiT/VAE 画布（保持相同宽高比），之后上采样到输出尺寸。

**--frames** _N_ | **--seconds** _N_

> 请求的时长。H3 会将帧数对齐到其 24 fps 时间网格。两者互斥。

**--steps** _N_

> 去噪轮数（默认为 **20**）。较低预算（例如 **4**–**7**）仅用于预览。

**--reuse** _N_

> 整个去噪器的复用间隔：**1** 较保守、**2** 快速、**3** 激进。与 **--core-reuse** 互斥。

**--layers** _N_

> 激活的 DiT 块：**50** 完整、**45** 快速、**40** 激进。

**--core-reuse** _N_

> 降低昂贵核心部分的刷新频率，同时保持 patch/head 工作的新鲜度。

**--token-reduction**

> 在中间 DiT 块中将水平方向的视频 token 成对处理（更快；可能改变构图）。

**--seed** _N_

> 随机数种子（默认为 **42**）。

**--first-frame** _PATH_, **--last-frame** _PATH_

> FL2VA 条件化图像。

**--ref-image** _PATH_, **--ref-video** _PATH_, **--ref-silent-video** _PATH_, **--ref-audio** _PATH_, **--ref-video-audio** _VIDEO_ _AUDIO_

> 有序的 Ref2VA 参考（可重复使用；顺序会被保留）。

**--show**

> 在 Kitty/iTerm2 类图形终端中显示渐进式预览。

**--profile**

> 打印各阶段的 Metal 计时和内存分配统计。

**--info**

> 检查模型结构和 Metal 设备，而不映射全部权重。

**-h**, **--help**

> 显示此构建版本的完整选项列表。

# INSTALLATION

在 macOS（Apple Silicon）上从源码构建。需要 **make**、C/ObjC 工具链以及 **PATH** 上的 FFmpeg：

```
git clone https://github.com/antirez/h3.c.git
cd h3.c
make -j8
./h3 --help
```

生成媒体前需要先下载 MiniMax-H3 权重树（例如下载到 **./MiniMax-H3**）。该项目没有发行版软件包；名为 **h3** 或 **libh3-bin** 的软件包是 Uber 的地理空间库，并非本工具。

# CAVEATS

需要支持 Metal 的 Apple Silicon、完整的 MiniMax-H3 权重树（数十 GiB）以及 **ffmpeg**/**ffprobe**。统一内存峰值占用很大；激进预设以保真度换取速度，可能改变构图。

**--reuse** 与 **--core-reuse** 不能同时使用。未经质量验证，不要叠加最激进的层数、复用和 token 缩减设置。命名冲突：其他生态中存在无关的 **h3** 二进制文件（例如地理空间 H3 工具）。

# HISTORY

**h3-metal** 是 **Salvatore Sanfilippo (antirez)** 于 2026 年推出的 C/Metal 项目，按连续的垂直切片构建（宿主元数据、Metal 块对等、提示词到视频/音频、FL2VA 和 Ref2VA）。它的目标是在不依赖 Python ML 技术栈的情况下实现 Mac 上的原生 MiniMax-H3 推理。

# TAGLINE

在邮件列表中处理补丁和拉取请求

# TLDR

**获取补丁系列**并应用到当前分支

```b4 shazam [message-id]```

**下载补丁系列**为可直接应用的 mbox

```b4 am [message-id]```

**在跟踪分支上开始新的补丁系列**

```b4 prep -n [topical-branch-name]```

**发送准备好的系列**给收件人

```b4 send```

**将完整线程取回**为 mbox 文件

```b4 mbox [message-id]```

**比较补丁系列的两个修订版**

```b4 diff [message-id]```

**为已合并的贡献生成致谢信**

```b4 ty```

# SYNOPSIS

**b4** [_-d_] [_-q_] [_--version_] _subcommand_ [_options_]

# DESCRIPTION

**b4** 是一个辅助工具，面向 Linux 内核以及众多托管于 lore.kernel.org 等 public-inbox 归档上的项目所采用的"邮件补丁"分布式开发工作流。它让贡献者可以准备并发送补丁系列，让维护者可以取回、验证并应用补丁，而无需手工整理邮箱。

给定 message-id 或归档 URL，b4 会找到整个线程，挑出系列的最新修订版，收集散落在各回复中的评审 trailer（Acked-by、Reviewed-by、Tested-by），并生成顺序正确的干净 mbox。它还能验证加密补丁证明、猜测基准提交，并把所有内容直接应用到工作区。

在贡献者一侧，**prep** 和 **send** 子命令将系列管理为一个被跟踪的分支，构建 cover letter 和收件人列表，并通过 SMTP 或 Web 提交端点发送补丁。

# SUBCOMMANDS

**am**
> 取回系列并将其写成可直接应用的 mbox。

**shazam**
> 取回系列并直接应用到当前 git 分支。

**prep**
> 创建并管理待提交的补丁系列。

**send**
> 将准备好的补丁系列发送给收件人。

**mbox**
> 将整个线程下载为 mbox 文件。

**diff**
> 生成系列两个修订版之间的 interdiff。

**pr**
> 处理发送到邮件列表的拉取请求。

**ty**
> 为已应用或已合并的系列生成致谢信。

**kr**
> 管理用于加密证明的贡献者公钥。

# CAVEATS

b4 要求上游项目使用 public-inbox 归档（例如 lore.kernel.org）。发送补丁需要配置好可用的 **git send-email** 或 SMTP。验证加密证明的前提是本地存有贡献者的密钥。

# HISTORY

**b4** 由 Linux Foundation 的 **Konstantin Ryabitsev** 编写。它起初只是一个叫 **get-lore-mbox** 的小脚本，后来随着成长为一套完整的贡献者和维护者工具集而更名为 b4（名字来自《星际迷航》中的仿生人角色 B-4）。它在 Linux 内核子系统工作流中被广泛使用。
